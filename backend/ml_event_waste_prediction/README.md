# SafaiMitra Event Waste Machine Learning Pipeline — Complete Engineering & Operational Guide

## 1. Executive Summary & Purpose

The **SafaiMitra Event Waste ML Pipeline** is a real-data-driven machine learning system designed to estimate the solid waste generated by temporary public and private gatherings (e.g., Marathons, Weddings, Religious Festivals, Exhibitions, Corporate Summits, and College Fests) and translate those estimates into actionable municipal dustbin allocations and collection schedules.

### Core Objectives:
1. **Predictive Accuracy**: Estimate total waste generation in kilograms ($\text{kg}$) based on empirical data rather than arbitrary guesswork or LLM hallucinations.
2. **Deterministic Segregation**: Apply municipal standards to break down waste into **Wet (Organic)**, **Dry (Recyclable)**, and **General (Residual)** bin requirements with configurable safety margins.
3. **Operational Transparency**: Surface ML confidence, training sample sizes, validation errors, and data coverage indicators to municipal administrators before final resource deployment.
4. **Continuous Learning**: Ingest post-event ground-truth collection records to retrain and continuously improve model performance over time.

## 4. Step-by-Step Operational Workflow (What to Do)

Follow this exact sequential workflow whenever you set up, update, train, or verify the ML pipeline.

### Step 1: Install Python Dependencies
Ensure your Python environment (Python 3.10+) has all required libraries installed:
```bash
cd backend/ml_event_waste_prediction
python3 -m pip install -r requirements.txt
```
*Dependencies: `pandas`, `numpy`, `scikit-learn`, `joblib`, `requests`, `pyyaml`.*

---

### Step 2: Download the Real Dataset
Fetch the real event waste records directly from the VISVA Sustainable Foundation portal:
```bash
python3 scripts/download_dataset.py
```
**What this script does:**
1. Connects to `https://visva.org.in/statistics/`.
2. Parses HTML data tables for all recorded events.
3. Saves the exact untouched raw CSV to `data/raw/visva_events_raw.csv`.
4. Writes provenance metadata (source URL, timestamp, record count) to `data/raw/metadata.json`.

---

### Step 3: Inspect and Profile Data
Generate an automated statistical profiling report of the downloaded dataset:
```bash
python3 scripts/inspect_dataset.py
```
**What this script does:**
1. Computes row counts, column types, missing values, and duplicate records.
2. Profiles participant range ($\text{Min}=100$, $\text{Max}=48,200$, $\text{Median}=1,000$).
3. Profiles total waste distribution ($\text{Min}=3.2\text{ kg}$, $\text{Max}=5,644.5\text{ kg}$).
4. Generates a structured JSON report saved to `data/processed/dataset_report.json`.

---

### Step 4: Preprocess and Clean Data
Transform the raw data into a clean, normalized training set:
```bash
python3 scripts/preprocess.py
```
**What this script does:**
1. **Deduplication**: Removes duplicated `(event_name, event_date)` rows.
2. **Numeric Normalization**: Strips symbols like `+`, `–`, `,`, `kg` and parses numeric quantities.
3. **Date Parsing**: Converts inconsistent date strings into standard timestamps.
4. **Target Calculation**: 
   $$\text{total\_waste\_kg} = \text{dry\_waste\_kg} + \text{wet\_waste\_kg} + \text{mix\_waste\_kg}$$
   *(Only applies if total waste is not already explicitly provided).*
5. **Feature Engineering**: Generates non-leaking features (see Section 5).
6. **Outputs Clean File**: Saves `data/processed/event_waste_training.csv`.

---

### Step 5: Train and Select Best Model
Train regression models, compare performance metrics, and serialize the winning model:
```bash
python3 scripts/train.py
```
**What this script does:**
1. Loads `data/processed/event_waste_training.csv`.
2. Performs an 80/20 train/test split with fixed `random_state=42`.
3. Trains Candidate 1: `RandomForestRegressor`.
4. Trains Candidate 2: `GradientBoostingRegressor`.
5. Compares validation metrics (MAE, RMSE, $R^2$) and selects the model with the lowest MAE.
6. Serializes the best model to `models/event_waste_model_v1.joblib`.
7. Exports metadata to `models/model_metadata.json` and `models/evaluation.json`.
8. Generates test set predictions with percentage errors in `data/processed/predictions.csv`.

---

### Step 6: Evaluate the Production Model
Run standalone evaluation on the saved production model:
```bash
python3 scripts/evaluate.py
```
**Output Metrics Example:**

### Step 8: Retrain on Newly Completed SafaiMitra Events
When sanitation staff records actual waste weights for completed events in MongoDB, run the continuous learning script:
```bash
python3 scripts/retrain.py
```
**What this script does:**
1. Merges new completed event records into the training matrix.
2. Trains a new candidate model version ($v1.1.0$).
3. Compares the new candidate's validation MAE against the production model ($v1.0.0$).
4. **Safety Rule**: If and only if $\text{MAE}_{\text{candidate}} \le \text{MAE}_{\text{production}}$, the new model is promoted and saved.

## 5. Feature Engineering & Target Leakage Prevention

### Target Variable:
- **`total_waste_kg`**: Total weight of solid waste generated by the event.

### Input Features (Non-Leaking):
| Feature Name | Type | Description / Derivation |
| :--- | :--- | :--- |
| `participants` | `float` | Estimated count of attendees / guests. |
| `log_participants` | `float` | $\log(1 + \text{participants})$ to capture non-linear crowd scaling. |
| `month` | `int` (1–12) | Month of event (captures seasonality & festival seasons). |
| `day_of_week` | `int` (0–6) | Day of week (0=Monday, 6=Sunday). |
| `is_weekend` | `int` (0/1) | Flag indicating Saturday or Sunday. |
| `quarter` | `int` (1–4) | Fiscal / seasonal quarter. |
| `type_Marathon/Sports` | `int` (0/1) | One-hot category for runs, marathons, cyclothons, sports. |
| `type_Marriage` | `int` (0/1) | One-hot category for weddings, receptions, engagements. |
| `type_Religious` | `int` (0/1) | One-hot category for annadanams, temples, yatras, poojas. |
| `type_Festival` | `int` (0/1) | One-hot category for melas, carnivals, utsavs, fairs. |
| `type_Exhibition/Bazaar` | `int` (0/1) | One-hot category for expos, markets, flea bazaars. |
| `type_Corporate` | `int` (0/1) | One-hot category for conferences, summits, workshops. |
| `type_School/College` | `int` (0/1) | One-hot category for campus fests, annual days. |
| `type_Community` | `int` (0/1) | One-hot category for NGO drives, cleanups, social rallies. |
| `type_Other` | `int` (0/1) | General gathering fallback category. |

> [!IMPORTANT]
> **Strict Anti-Leakage Rule**:
> `dry_waste_kg`, `wet_waste_kg`, and `mix_waste_kg` are **NEVER** used as input features to predict `total_waste_kg`. Doing so would allow the model to cheat by summing the inputs, resulting in false 100% accuracy that fails completely in real-world deployment.

## 6. Deterministic Municipal Bin Requirement Engine

The ML model predicts the estimated total waste weight ($\text{kg}$). A deterministic municipal engine then translates that weight into segregated bins and logistics plans.

### Formulas & Sizing Logic:

1. **Required Municipal Capacity**:
   $$\text{Required Capacity (kg)} = \text{estimated\_waste\_kg} \times \text{safety\_factor}\quad (\text{Default safety\_factor} = 1.25)$$

2. **Total Dustbins Needed**:
   $$\text{Total Bins} = \max\left(\text{min\_bins},\; \left\lceil \frac{\text{Required Capacity}}{\text{bin\_capacity\_kg}} \right\rceil\right)\quad (\text{Default: } 45\text{ kg per bin}, \text{min} = 2)$$

3. **Segregation Split**:
   - **With Catering / Food Service**:
     $$\text{Wet Bins} = \max(1, \lceil \text{Total Bins} \times 0.55 \rceil)$$
     $$\text{Dry Bins} = \max(1, \lceil \text{Total Bins} \times 0.30 \rceil)$$
     $$\text{General Bins} = \max(1, \text{Total Bins} - (\text{Wet Bins} + \text{Dry Bins}))$$
   - **Without Food Service**:
     $$\text{Wet Bins} = \max(1, \lceil \text{Total Bins} \times 0.15 \rceil)$$
     $$\text{Dry Bins} = \max(1, \lceil \text{Total Bins} \times 0.60 \rceil)$$
     $$\text{General Bins} = \max(1, \text{Total Bins} - (\text{Wet Bins} + \text{Dry Bins}))$$

4. **Municipal Risk Scoring**:
   - $\text{Estimated Waste} \ge 1,000\text{ kg} \implies \mathbf{CRITICAL\text{ }RISK}$
   - $\text{Estimated Waste} \ge 400\text{ kg} \implies \mathbf{HIGH\text{ }RISK}$
   - $\text{Estimated Waste} \ge 150\text{ kg} \implies \mathbf{MEDIUM\text{ }RISK}$
   - $\text{Estimated Waste} < 150\text{ kg} \implies \mathbf{LOW\text{ }RISK}$

5. **Daily Collection Frequency**:
   - $\text{Estimated Waste} > 750\text{ kg} \implies 3\times\text{ daily}$
   - $\text{Estimated Waste} > 300\text{ kg} \implies 2\times\text{ daily}$
   - $\text{Otherwise} \implies 1\times\text{ daily}$

## 7. Node.js Backend Integration

The existing Node.js / Express backend connects to the Python ML prediction service through `backend/services/MLPredictionService.js`.

### How Node.js Invokes the Model:
```javascript
// backend/services/MLPredictionService.js
const { execFile } = require("child_process");
const path = require("path");

const ML_DIR = path.join(__dirname, "..", "ml_event_waste_prediction");
const PREDICT_SCRIPT = path.join(ML_DIR, "scripts", "predict.py");

class MLPredictionService {
  async predict(eventData) {
    return new Promise((resolve, reject) => {
      execFile(
        "python3",
        [PREDICT_SCRIPT, "--json", JSON.stringify(eventData)],
        { cwd: ML_DIR, timeout: 8000 },
        (error, stdout, stderr) => {
          if (error) return reject(error);
          const result = JSON.parse(stdout);
          resolve(result);
        }
      );
    });
  }
}
```

### Endpoints Available:
- **`POST /api/event-dustbin-requests`**: Automatically invokes the ML prediction service upon citizen submission.
- **`POST /api/event-dustbin-requests/:id/predict`**: Allows municipal admins to re-run and re-evaluate ML predictions for an existing request in real time.
- **`GET /api/admin/event-dustbin-requests/analytics/ml-performance`**: Returns model accuracy metrics (MAE, RMSE, $R^2$, sample count).

```yaml
  version: "v1.0.0"

  fallback_algorithm: "GradientBoostingRegressor"
  test_size: 0.20

  model_save_path: "models/event_waste_model_v1.joblib"
  metadata_save_path: "models/model_metadata.json"
  evaluation_save_path: "models/evaluation.json"

bin_requirement_engine:
  bin_capacity_kg: 45.0
  safety_factor: 1.25
  waste_ratios_with_food:
    wet: 0.55
    dry: 0.30
    general: 0.15
  waste_ratios_no_food:
    wet: 0.15
    dry: 0.60
    general: 0.25
  min_bins: 2

data_coverage:
  min_participants: 50
  max_participants: 35000
```
