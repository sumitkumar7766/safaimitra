# 🗄️ Database Strategy for Large-Scale Cities (Live System)

## 🧠 Start With This Line (Must Say)

> **“Our database strategy is designed to scale city-by-city, not all at once, which keeps cost controlled and predictable.”**

---

## 🏙️ Scenario: Multiple Cities Go Live

* 10 cities → pilot
* 50 cities → state-level
* 100+ cities → national-level

👉 Database ko **gradually scale** kiya jaata hai.

---

## 1️⃣ Database Choice (Why MongoDB)

We use **MongoDB** because:

* Horizontal scaling support
* Flexible schema (city-wise data)
* High read/write performance
* Cloud-managed (MongoDB Atlas)

Perfect for **municipal multi-city data**.

---

## 2️⃣ City-wise Data Separation (Very Important)

### 🔹 Logical Separation

* Each record has:

```json
{
  "cityId": "BHOPAL_01",
  "wardId": "WARD_12"
}
```

👉 Queries city-specific hoti hain → fast & efficient.

---

### 🔹 Optional: City-wise Databases (Future)

* Big cities get separate DB
* Small cities share cluster

👉 **Cost optimized hybrid model**

---

## 3️⃣ Database Scaling Model

### 📦 Phase 1: Pilot (1–5 Cities)

* MongoDB Atlas Free / M2
* Cost: ₹0 – ₹1,000 / month

---

### 📦 Phase 2: Medium Scale (10–30 Cities)

* MongoDB Atlas M5
* Cost: ₹4,000 – ₹6,000 / month
* Handles millions of records

---

### 📦 Phase 3: Large Scale (50+ Cities)

* MongoDB Atlas M10+
* Cost: ₹12,000 – ₹25,000 / month
* High availability + backups

---

## 4️⃣ Cost per City (Very Important for Judges)

### Example: 50 Cities

* Total DB cost: ₹20,000 / month
* Cost per city:

```
₹20,000 / 50 = ₹400 per city per month
```

👉 **Extremely affordable for municipalities**
